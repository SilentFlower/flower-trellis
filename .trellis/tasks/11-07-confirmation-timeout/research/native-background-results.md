# 原生后台终端验证结果

- 日期：2026-11-07。
- 当前任务仍为 `planning`；本轮只改研究文件并运行隔离探针，没有实现产品代码、启动任务、提交或推送。
- 所有模型响应来自 `127.0.0.1` mock，使用 dummy key，没有真实模型推理调用。测试的是实际 CLI、终端工具、任务通知和交互调度；没有验证真实模型是否总能遵循产品规则。
- 可复核的关键时序保存在 [native-background-evidence.json](native-background-evidence.json)，完整实验摘要位于其中列出的临时目录。

## 已观察到的结果

| 实验 | 实际时序 | 结论 |
| --- | --- | --- |
| Claude 2.1.293 普通 TUI，保持打开 | 19.073s 返回真实后台任务标识；19.144s 显示最终 `FLOWER_WAITING`；22.167s 自动发起新主请求，新增 completed 的本探针 task-notification；22.225s 显示 `FLOWER_RESUMED` | 最小自动续接通过。等待阶段没有用户输入，没有 TaskOutput 或模型轮询。 |
| Claude 普通 TUI，正常退出 | 1.139s 显示等待；1.640s / 1.891s 发送 Ctrl+D；1.904s 确认原生 “Exit and stop tasks” 菜单；2.242s CLI 退出；观察至9.140s仍只有两次主请求 | 此正常退出场景通过；必须真正确认退出，打开退出菜单不等于进程已经退出。 |
| Claude 普通 TUI，强杀专用 CLI | 3.120s 显示等待；3.623s 强杀本实验 CLI；3.745s观察到退出；观察至11.121s仍只有两次主请求 | 此强杀场景通过。根控制器继续保留 mock 观察，未在强杀时立即关闭服务来掩盖后续请求。 |
| Codex 0.167.0 TUI，`--no-daemon`，250ms 终端返回 | 1.835s 工具先返回后台 session；1.841s 显示最终等待；4.519s 旁观到本实验 Python 结束；观察至9.841s没有第三次主请求 | 此模式未观察到后台结束自动续接，不能作为本功能的触发依据。 |
| Codex 同模式，1000ms 终端返回 | 2.564s 工具先返回后台 session；2.569s 显示最终等待；4.519s Python 结束；观察至17.569s没有第三次主请求 | 增大终端返回时间和观察窗口后仍未观察到续接。 |
| Codex 独立 App Server + 原生 remote TUI，250ms 终端返回 | 2.244s 工具返回后台 session；2.253s 显示最终等待；4.930s Python 结束；观察至17.254s没有第三次主请求 | 保持专用服务运行的对照同样没有观察到空闲续接。不是默认 managed daemon 验收。 |

Claude 首次普通 TUI 的启动阶段处理过一次专用实验目录的信任提示，发生在第一主请求前；之后等待阶段没有输入。bare 模式的排障结果没有用于普通 TUI 的成功判据。

Codex 的 `exec` 对照确实调用了原生终端并返回后台 session，但 exec 在最终回答后退出，因此不作为空闲 TUI 的续接证据。普通 TUI 请求中的自动标题生成属于另一个 thread，探针按真实 `client_metadata` 的 thread/source 区分，辅助请求不计入主请求。

## 证据边界

1. Codex 本轮测试了 `--no-daemon` 与独立 App Server + remote TUI。没有将其结果泛化为默认共享 daemon、IDE、其他版本或所有配置，也没有操作当前真实会话或停止共享 daemon。默认 daemon 的隔离接口核查见 [codex-daemon-isolation.md](codex-daemon-isolation.md)。
2. 本轮用 PTY 可见的最终文本和已发送的 Responses / Messages 最终响应作为等待边界；没有独立订阅 Codex App Server 的 `turn/completed` 或终端退出通知。无第三次主请求不等于宿主没有任何 UI 状态事件。
3. Claude 的三个通过项是三秒计时的最小能力验证，尚未验证人工回复撤销、临界竞争、手动重开旧事项、100 / 130 / 200 秒及 Windows / IDE。这些仍是正式自动开启前的必测项。
4. 本轮只打印固定回执，没有执行真实 Brief 开工、问题修复、commit 或 push；没有验证超时授权状态机。
5. 原生后台进程和 session 标识本身不足以证明窗口仍存在；退出后不唤醒、跨会话不重放仍须适配单独保证。

## 对规划的影响

- 用户要求优先验证原生后台终端，已先做真实 CLI 探针。Claude 的原生 Bash 完成通知可以保留为候选主路径。
- 当前证据尚不能支持把“原生后台终端完成”作为 Codex 与 Claude 的统一自动触发器，也不能据此默认开启 Codex 自动确认。
- 不自行新增 Flower 启动器，不以 queue / resume 补造回调，不改用户已确认的时间和提交规则。
- 若后续仍无满足原启动方式的 Codex 路径，需要用户决定：接受 Codex 的补充前台接入，或调整首版兼容范围。该决定将改变 R6 / R12 的交付边界；研究结论本身不替用户选择。
