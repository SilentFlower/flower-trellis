# 放宽后台确认的 Git 快照、会话日志与材料预算

## 目标

大仓库、长会话和较大的计划文件可以通过后台确认，同时保留同一份计划的完整校验。

## 背景

`vibecoding-bench` 的整仓索引为 6,154,787 字节，当前 4 MiB 限制让包含该仓库的 Push 计划在准备阶段回退人工。`confirmation_policy.py` 对 Git stdout 和不同用途的普通文件设置了统一硬门槛。Codex 已增量解析会话，Claude 核验时重复读取整个 transcript。运行时还有旧 Node 实现留下的 15 秒、2 MiB、1 MiB 预算，以及共用的 300 秒展示与领取期限。

## 需求与验收

- **R1 Git 与文件**：移除整仓 Git 输出 4 MiB 和仅用于哈希的文件 512 KiB 门槛；保留索引、工作区、暂存和计划文件复核。超过原上限的索引与计划文件通过准备；修改索引、暂存区、计划外工作区或计划文件会作废旧许可。
- **R2 会话记录**：移除 Codex 128 MiB 和 Claude 16 MiB 的整份文件门槛。长记录与大体积无关日志行可核验近期确认事件；保留截断、替换、来源歧义、人工输入和不完整通知的拒绝场景。资源消耗不得随每次轮询重复扫描整份历史。
- **R3 预算**：分别处理需要解析或展示的材料、策略输出和状态存储。用真实规模的单仓与多仓记录测量耗时和尺寸，再定运行预算；失败应指出阶段、触发条件以及适用的仓库或命令。展示期限和领取期限独立定义和验证。
- **R4 安全与兼容**：保留精确展示、身份绑定、输入取消、领取及 started 复核。旧请求沿用安装器升级取消；保持合法配置、默认用户倒计时和公开命令语义。

## 范围边界

原生 Windows 自动确认由兄弟子任务交付。业务仓库测试采用只读快照；提交、推送、发版及外部项目安装升级各自沿用现有流程。
