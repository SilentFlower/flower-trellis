# 简化 Worktree 创建与分支本地准备流程

## Goal

让用户按选定基线一次建立独立工作区，常见工具准备自动完成，可恢复问题有明确状态和继续方式，减少环境检查、失败回滚和重复确认。

## Background

- 用户在本会话先要求结合截图和历史会话排查，再要求整体优化，目标是“简单、可用、卡点少”。
- 2026-10-21 的 xhgj-ai-harness 会话 `01a15cab-bcd0-7fa2-bdf9-676b5342f8bb` 依次暴露根仓遗漏、旧任务脚本拒绝参数、四条 Patch 摘要过期、源安装与目标基线版本不同、Git 忽略的 Codex 配置缺失。
- 同版本 Plugin 重应用核对 173 个文件内容未变，只修正本机记录；最终通过原生 Git 创建及目标独立初始化完成准备。证据、实现锚点和历史设计见 `research/findings.md`。

## Requirements

### R1 — 以目标基线建立工作区

- 新工作区以用户明确选择的 Git 提交为准；默认仍从调用目录对应根仓当前分支选择基线。
- 创建不要求先修好源窗口 Flower 安装、提交无关升级、清空其它窗口改动或让源/目标安装版本相同。
- 创建 Git 目录可以独立于 Trellis 任务；未请求任务时无需提供任务标题或 slug，已提供的旧参数继续有效。
- 依据：`src/lib/worktree-flower-state.js:146`、`src/commands/worktree.js:167`，现有行为使本机安装异常成为创建前置条件。

### R2 — 一次预检与有效确认

- 预检只校验 Git 创建依赖，并提示基线缺少 Trellis/任务脚本等已知事项；不在创建前重放安装包或制作整仓镜像。工具准备在实际目标目录中执行。
- 保留一次明确的创建计划确认。确认内容包括仓库、目标路径、分支、基线、可选任务，以及仅补本地状态和缺失忽略配置的准备边界。
- 未复制的源 dirty 清单、未操作子仓的现场变化不使计划失效；实际基线、目标、写入载荷或必要授权变化仍需更新计划。
- 不对每个可恢复问题单独询问，也不重复确认已由用户指定的子仓基线。
- 依据：`vendor/skill-garden/.trellis/0.6/scripts/worktree_setup.py:1263`，展示信息整体进入指纹造成无关变化影响确认。

### R3 — 可恢复的准备与准确交接

- Git 创建成功后，工具配置、安装信息或任务初始化失败时保留新目录与分支，并准确区分“工作区已创建”“工具全部就绪”和“仍有待准备项”。
- 未完成项给出具体原因、路径和继续方式；本地配置/安装准备通过 prepare 重试，任务异常由目标 task.py 的具体命令处理。prepare 不自动创建、恢复或修改任务，不需删除重建工作区。
- 路径冲突、覆盖已有内容、跨目录写入与损坏恢复证据仍阻止相关写入，不因希望减少卡点而忽略。
- 依据：`vendor/skill-garden/.trellis/0.6/scripts/worktree_setup.py:1347`，目前任意准备异常都会进入整目录删除补偿。

### R4 — 目标独立准备安装信息

- 默认只使用目标自身声明、lock 和 state，不读取源安装记录；来源继承仅保留已有的显式 --inherit-flower --source 入口，且仍严格校验。
- 源摘要过期、源/目标版本不同、Flower 元数据缺失或无关项目配置变化，不阻止 Git 创建或可独立进行的 Trellis 工作。
- 能取得与目标锁定身份一致的安装包，且现有文件内容无需变化时，自动补齐本地安装记录；受管且被 Git 忽略的缺失本地配置可以独立生成。
- 自动准备不修改目标现有受版本控制文件，也不复制来源个人配置。旧包不可用、需改内容或需新增授权时，保留待准备状态，不自动升级基线或冒充安装成功。
- 依据：`src/plugin/install/state-validation.js:37` 以整文件摘要判断 Patch；`src/builtin-plugins/skill-garden/provider.js` 当前只提供随本版发布的固定包，不能保证旧版可重建。

### R5 — 旧脚本兼容与任务可选

- 按目标实际支持的接口初始化 planning 任务，缺少新版 create 参数时采用已核实的兼容方式；能力不明则保留任务待准备。
- 创建任务不激活来源会话，不进入实现，也不修改目标分支的任务脚本来迎合外部工具。
- 任务只在 create 显式请求时尝试一次；后续 prepare 不触碰任务。部分创建后保留真实路径和需求文档，并给出尚未成功的目标任务命令。
- 依据：原会话 task-command-failed 回执；`research/findings.md` 记录旧版 create 会自动绑定来源会话，不能只删除 no-start 参数。

### R6 — 根仓与子仓边界

- 默认使用 Trellis 项目根仓，明确本次实际操作的 Git 仓库，避免只创建业务子仓而遗漏外层规范。
- 展示选定提交的子模块及配置中的独立 Git 包；已有明确授权的子仓基线和分支写入交接，未指定的各仓独立确认。
- 后续业务规划在以目标目录为工作区根的新会话继续，只读取目标分支自己的规范与运行态。

### R7 — 校验一致且不过度阻断

- Plugin verify 对普通受管路径与 Patch 目标的摘要检查范围一致，共用可复用的诊断逻辑；相同目标无需重复计算摘要。
- 安装管理中的真实漂移保持可见，不能用直接重算当前文件摘要替代包依据。
- 保留必要的路径、分支、基线、写入前漂移、包完整性、并发锁以及 remove/migrate 的保护。
- 依据：`src/plugin/application-service.js:549` 未遍历 patches，`src/plugin/install/state-validation.js:37` 会检查，导致两个入口结论不同。

## Acceptance Criteria

- [x] AC1 / R1-R4：源安装有过期摘要或升级未提交、目标仍为旧版时，创建无需先修源目录或升级主分支；各步骤有准确状态。
- [x] AC2 / R3-R4：目标缺少被忽略的 Codex 配置且可同版本生成时，自动生成独立配置及记录；原窗口及目标 tracked 文件内容不变。
- [x] AC3 / R3-R5：旧脚本可按核实接口创建 planning 任务且不产生来源会话绑定；未知接口或任务异常保留工作区，并能恢复或明确给出下一步。
- [x] AC4 / R1-R2：只创建 Git 工作区无需任务参数；旧的 title/slug 调用继续支持；基线可解析但没有 Trellis 的分支能够建目录并提示需要初始化。
- [x] AC5 / R2：无关 dirty/子仓现场变化不要求重确认，真实基线、目标、写入载荷与必要授权变化仍被识别；预检不写源/目标仓库。
- [x] AC6 / R3-R4：缺固定包、坏记录、真实内容冲突或禁用/恢复状态不被报为完整就绪；不隐式联网、升级或覆盖配置。
- [x] AC7 / R3-R5：prepare 可重复执行本地状态与目标安装准备，完全不触碰任务，不覆盖已有记录或需求文档；显式继承的恢复证据继续受保护。
- [x] AC8 / R6：根仓加业务子仓场景的仓库、基线及交接清楚，源窗口的分支、工作区和会话不受影响。
- [x] AC9 / R7：verify 能同时报告普通路径及 Patch 摘要异常，继承与 verify 共用检查规则；安全边界及既有 remove/migrate 回归通过。
- [x] AC10 / 全部：Flower 源、Skill-Garden 作者源、发布快照、相关技能与规范一致，隔离验证覆盖本次真实卡点；受影响行为通过原生 Ubuntu/Windows 的必要 CI 验证，未经执行的平台不宣称兼容通过。

## Out of Scope

- 软件发版、生产变更，以及用户业务仓库的实际迁移或升级。
- 自动下载或升级未知旧版安装包，自动修复真实业务/规范内容冲突。
- 全局改造 Plugin Patch provenance/schema；本轮通过缩小 worktree 阻断范围解决共享配置问题。
- 自动遍历全部子仓创建业务分支，或新增跨仓发布/事务框架。
- 继承当前任务、session、auto-loop、缓存、事务、备份与控制状态。

## KISS 收缩决定

- 用户明确要求收缩实现：默认目标准备单路径；去掉整仓安装预演、默认来源回退及 setupRequest 任务自动恢复。
- 保留 Git 创建/准备分离、可选任务、已知旧接口兼容、目标固定包补齐忽略配置和必要安全边界。
- 不新增 registry schema 字段，不建立跨命令的任务恢复机制；安装缺版本依据时给具体待办，Git 工作区保持可用。
