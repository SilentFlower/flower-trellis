# 改进 Brief 关键取舍披露与规划边界审查

## Goal

让用户通过简短的任务交接摘要，看清目标、方案以及影响实际使用的重要限制和重大决定，并在规划阶段处理造成使用缺口的范围取舍。

## Background

- 用户反馈 Brief 隐藏或弱化限制，实施后反复返工；同时明确要求保留交接摘要的用途，拒绝扩成详细评审稿。
- 用户接受保持摘要结构、突出关键取舍的方向，并要求重要限制和重大决定使用加粗或其他醒目方式展示。
- 已核对外部项目会话 `01a1ed1b-8f82-7600-8044-64367bdae57a`：清单容量先由 16 MiB 提至 64 MiB、CPU 代际校验阻断跨机迁移、迁移专用修复留下普通准备入口的容量限制、失败迁移租约阻塞升级。该会话用于需求案例。
- 当前 Brief 已含八段结构和关键决定字段；实际生成规则偏重摘要字段，规划 Quality Bar 对沿用限制的必要性及完整使用路径缺少明确审查要求。

## Requirements

- **R1 摘要定位**：保留 Goal、Scope、Non-Goals、可选 Technical Overview、Context & Decisions、可选 Risks、Acceptance、Next Step 的职责和顺序。优先概括用户结果、方案和关键取舍；详细设计、完整测试矩阵及决策台账继续由原材料承载。
- **R2 关键影响披露**：从最新规划材料提取会改变使用方式、可用范围、兼容性、交付结果的重要限制、重大决定及具体影响。区分已收敛决定、仓库事实、尚待验证风险及待决定事项；材料遗漏或决定未收敛时先回到规划补齐。
- **R3 醒目展示**：默认采用 Markdown 加粗与【重要限制】【关键决定】【交付风险】【待决定】等明确标签，标亮具体影响。通常优先突出 3～5 处；这是阅读建议，重要内容完整性优先。颜色仅作支持场景下的辅助，重点文字本身可独立表达含义。
- **R4 边界审查**：规划中新增或沿用阻断正常使用的条件，须检查依据、保护对象、必要性、替代方案及对原目标的影响。既有实现只能作为现状证据。排除正常场景、改为拒绝或转交人工的未决产品取舍，应按现有规则收敛。
- **R5 用户路径闭环**：从用户最终完成操作的路径核对相关入口和恢复、升级等必要衔接。不能用局部功能验收代替整体结果；范围排除项若阻断目标，须暴露影响并解决取舍。保留适用授权、数据保护与必要校验。
- **R6 分发一致性**：从 Skill-Garden 0.6 作者源修改并同步发布快照、各平台最终目标及当前项目投影；Brief 与 Brainstorm/readiness 消费方采用同一 owner 契约。

## Acceptance Criteria

- [x] **A1 → R1、R2**：Brief 技能和模板保留原结构；通过真实任务材料对照，关键影响进入摘要，技术细节留在三件套。
- [x] **A2 → R3**：模板和生成指令提供加粗标签示例；3～5 处为软建议，超过数量的重要信息继续保留；纯文字显示时仍可读。
- [x] **A3 → R4、R5**：规划收敛/Quality Bar 明确检查限制依据、未决取舍和完整路径；沿用旧门槛、专用入口修复、回退人工及相互阻塞案例有对应规则覆盖。
- [x] **A4 → R2、R4**：待决定标签仅作披露；实际开工沿用既有需求收敛、Brief 确认和增量决定规则。Brief 中的新增事实可追溯到规划材料。
- [x] **A5 → R6**：相关规则专项、Patch 冲突、快照、compiled targets、strict budget 和输出模板验证通过，作者源与投影一致。

## Scope Boundaries

- 交付对象为 Brief 与规划规则及其分发验证。外部业务项目的迁移、CPU 画像、容量和线上升级由其现有会话处理。
- 保留现有 task-start、确认计时、授权、增量评审和 auto-loop runner 合同。规则重点为信息选择、展示与规划语义审查。
- 历史任务材料按本次需要读取；现有任务不会因此批量重写或重新审批。
