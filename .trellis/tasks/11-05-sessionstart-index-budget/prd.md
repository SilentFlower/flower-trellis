# 修复大型仓库 SessionStart 索引注入超限

## Goal

让大型仓库在会话重建时获得完整、预算内的 Trellis 上下文，并能按当前任务发现所需规范。

## Background

- 用户在 2026-11-05 报告 `/root/project/xiaoxian-desktop` 压缩恢复后出现 `Trellis state 注入为 34603 字符，超过 8000 字符预算`。原始会话和宿主保存的全文确认：499 个规范索引的路径列表占 28021 字符，宿主交付中间截断并遗漏 `task-status` 等信息。
- 根因位于受影响项目 `.codex/hooks/session-start.py:578` 的全量索引输出；`.claude/hooks/session-start.py:927` 存在相同片段。`src/assets/flower_session_start.py:421` 负责保留全文并输出可见告警。完整证据及作者源归属见 `research/sessionstart-evidence.md`。
- 规划阶段的内存模拟替换列表后，该样本为 6713 字符，任务状态、workflow-state、代码设计、Codex 交互和模型提示逐字保留；该数字仅证明方案体积，后续真实运行、更新及宿主接收的验证状态见 `validation.md`。

## Requirements

- **R1 — 控制动态索引体积**：默认上下文不随规范索引数量和路径长度线性增长；在当前 pinned full 工作流下覆盖 0、少量、499、1000 个索引及合法长路径，真实三段输出分别不超过 8000 字符。
- **R2 — 保留规范发现能力**：准确显示可用索引总数，通用指南、当前任务上下文清单及按关键词发现规范的入口可达；缺失指南不生成无效路径，完整目录仍能按需查询。
- **R3 — 保留恢复信息**：两平台的 `startup`、`clear`、`compact` 保留完整当前任务、工作流、平台和模型规则，兼容无活动任务和进行中任务；已有会话绑定、条件刷新、禁用、恢复事件及宿主显式额度语义保持一致。
- **R4 — 持久交付与验证**：修复覆盖拥有同一输出片段的既有平台，经过标准安装和更新持续生效；作者源、发行快照和编译目标一致，重复应用幂等，并在受影响项目核对真实宿主接收情况。

## Non-Goals

- 调整全局字符预算、宿主额度或压缩策略。
- 自动推断包依赖并创建新的规范选择系统。
- 改动 `xiaoxian-desktop` 的产品源码、业务任务范围或其会话历史。
- 软件包发版、全局 CLI 升级或部署外部服务。

## Acceptance Criteria

- [x] **AC2 / R2**：索引总数准确、缺失指南不生成无效路径、已有规范能由任务清单或发现入口找到。
- [x] **AC3 / R3**：两平台的三种重建事件在无任务和进行中任务下保留完整关键块；既有条件刷新、禁用、恢复与模型提示回归通过。
- [x] **AC4 / R4**：受影响平台的最终生成结果符合约定，源 Patch、快照和编译目标一致；隔离更新可重复应用且不改变宿主显式额度。
- [ ] **AC5 / R4**：记录受影响项目更新前后输出尺寸及真实宿主接收证据；历史全文和任务文件仍可读取，未取得宿主证据时明确记录待验。
