# Brief — 补齐 worktree 的 Flower 安装信息继承

## Goal

- 使用 worktree skill 后，目标具备与分支内容相符的独立 Flower 安装信息。

## Scope

- create 自动纳入继承；已有 worktree 缺记录时，由 skill 调用 prepare 补齐。
- 补齐声明、lock、经验证的 state 和适用设置；更新引擎、技能、快照及回归测试。
- 修复版本未知时误报已最新的问题，作为兜底。

## Non-Goals

- 不复制缓存、事务、备份和控制状态，不自动升级或覆盖目标分支内容。
- 保留原有两个 .flower 配置及其它无关改动；本轮不发版、不自动提交推送。

## Key Decisions

- 目标已有记录优先；源记录与目标内容校验一致后，才补入缺失文件。
- 来源和待继承内容纳入创建指纹；失败回滚，文件独立，后续互不影响。
- 纯 Trellis 继续可用；版本未知不触发重装或阻塞式更新提示。

## Key Context

- 修改 Flower src/ 和 Skill-Garden 作者源，再同步 enhancements/；skill 调用引擎完成同步。
- 已复现缺失记录误报；全部联调在隔离项目进行，重任务经 wsl-safe-run 串行执行。

## Risks / Deferred

- 旧分支或未提交插件内容可能不匹配，此时报告冲突，内容修复另行处理。
- Node/Python 调用与回滚、新查询状态的兼容性需要回归验证。

## Acceptance

- .flower 被忽略时，创建和补配仍能继承有效记录；重复执行无变化，源目标互不影响。
- 冲突、损坏、软链接及中途失败不覆盖目标、不留下误导性安装记录。
- 缺失兜底、现有更新行为、源码快照和质量门禁通过，原有改动保留。

## Next Step

- 实现、检查、规范及两仓业务推送已完成，任务为 completed；等待后续安排。
