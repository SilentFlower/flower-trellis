# 后台确认容量基线

## 本地测量

| 样本 | 证据 |
| --- | --- |
| `vibecoding-bench` 整仓索引 | 6,156,863 字节；原 4 MiB 预算明确拒绝。实际只读流式快照通过，首轮 1.575 秒。 |
| 实际三仓 | `vibecoding-bench`、其 `cc2api` 子仓和 `cc-runtime-bridge`，各取一个现有文件作为精确计划。完整只读快照通过，热缓存一轮 0.472 秒，仓库 facts 序列化为 2,552 字节。 |
| 隔离双仓 20,000 路径 | 每仓 10,000 个 42 字符左右的普通文件路径。策略输入 920,374 字节，输出 3,702,208 字节，真实 Python 策略命令 3.282 秒，退出 0。旧输入和输出门槛都低于实测负载。 |
| 较大 Check 计划 | 12,000 条检查记录和约 64 KiB 正文；输入超过 512 KiB，准备后的状态不足 4 KiB。正式领取仍返回完整上下文。 |
| 合成长会话 | 136 MiB 以上会话文件、8 MiB 工具记录、分两次写入的末行；首读接受旧门槛以上日志，后续只处理新增完整行，替换文件拒绝旧观察。 |

本地样本用于量级验证，耗时不是各平台的性能保证。

## 预算分工

- 整仓 Git 输出、仅哈希的普通文件和整份会话文件都没有固定字节上限。Git 的 64 KiB 分块是 I/O 粒度。
- 保留单条 Git 命令 10 秒的执行保护；新增 Push 快照总计 30 秒；外层策略进程 40 秒。双仓压力样本约 3.3 秒，分层上限为慢盘、进程启动和跨平台差异留余量。外层比快照多 10 秒供其报告错误和序列化。
- 输入 JSON 1 MiB、结构化文档和冻结正文 512 KiB。输入预算覆盖实测双仓清单；正文预算单独控制展示成本。原生最终展示预留 768 KiB 含首尾说明。
- 策略输出 16 MiB；实测 3.53 MiB，较大的仓库事实还会包含摘要、模式、路径和链接目标。状态改存冻结材料的摘要，2 MiB 状态预算为 Claude 最终展示及 JSON 表示留余量；控制文件和锁元数据保持独立。
- 原生 JSONL 单条解析上限 16 MiB；已验证整份文件增长和超过旧 2 MiB 的单条无关记录。原生消息超过单条解析预算时有独立的人工回退原因。
- 保持现有 300 秒展示与 300 秒领取兼容值，拆为两个独立期限。前者防止正文一直未展示，后者防止过期唤醒获得许可。用户设置的倒计时沿用原配置。

## 原生 Windows 文件状态回归

- 根因（隐含假设）：Windows Python 3.12 对未修改的同一文件，按路径 `lstat` 和按句柄 `fstat` 返回的 `st_ctime_ns` 可不同。隔离探针中只有这一字段出现差异。原实现把差异当作材料被改动。
- 修复：Windows 跨来源比对设备、文件身份、模式、大小和修改时间；读取前后用同一打开句柄额外复核 `st_ctime_ns`。Linux 保留原时间戳核验。两条材料读取路径共用这套规则。
- 预防：补充可重现的 Windows 跨来源时间戳、文件身份漂移和同句柄变化回归。相邻的原生日志读取本来就不跨来源比较 `st_ctime_ns`。
- 复验：Windows NT 10.0.26200、Git 2.45.1.windows.1，以 Windows 临时目录中的隔离源码和真实 `win32` 解释器执行六组确认专项。Python 3.8.10 和 3.12.2 各 53 项，44 通过、9 个 Linux 专属用例跳过，均退出 0。WSL/Linux 定向回归 42 项通过。原生 Windows Codex / Claude 宿主自动确认属于后续子任务。
- 规范交接：将跨来源与同句柄比较的字段语义交给 Check-All 后的 Update-Spec，保留 Windows 实机证据供复核。
