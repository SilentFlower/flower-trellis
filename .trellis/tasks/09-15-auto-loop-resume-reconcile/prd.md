# 补齐 Auto-Loop 恢复阶段的三轮自动自纠

## Goal

Auto-Loop 在路径登记或上下文恢复过程中遇到可归因、可逆的内部操作错误时，自动完成诊断、纠正、复核和续跑，最多三轮；首次错误不直接结束队列并等待用户。

## Requirements

- R1：路径登记有明确语义，并在写入决策之前校验可由仓库证明的错误，返回可执行的修正信息。可保存必要诊断和纠正审计，但不得写入无效决策、替换原文档基准或提前改变任务阶段；既有合法代码文件登记用途保持。
- R2：恢复时保留未完成 action、原文件基线和待消费决策，重复读取不重设检查基准；已登记且可核验的文档变化不能被当作实现完成，也不能仅因未 record 就结束队列。
- R3：运行期间可恢复的文档路径登记与恢复漂移进入诊断→agent 自动纠正→runner 校验→继续原 action 的闭环，最多三轮实际纠正。首次诊断、单纯查询、上下文恢复和同一纠正的回执重放不消耗新次数；该能力不扩展为所有错误的通用自修系统。
- R4：修正必须依据任务、原决策、基线及真实文件差异，不得通过接受当前全部变化扩大授权；未知外部修改、受保护文件、越权、不可逆或超预算保持阻塞。旧错误记录保留，纠正须可追溯，不倒改历史授权。
- R5：保留现有检查、提交修复、依赖调度和本地提交边界；独立任务不被无关失败连带阻塞，不自动 push、发布或归档。
- R6：同步 canonical runner、相关技能/恢复指引、发布快照和必要测试；不改其他项目的历史运行状态。

## Acceptance Criteria

- [x] AC1（R1/R3/R4）：新登记错路径能在写入决策前发现并修正；复现旧错路径与恢复序列，错误可由 agent 在原 run/action 内纠正，无需用户 retry-blocked，原决策、代码和提交保留。
- [x] AC2（R2）：正确登记后修改文档、实施未完成时恢复，继续原 action；重复 next 保留原 issued_at、baseline、深度和路由，不能提前完成实施或消费尚无结果的检查。
- [x] AC3（R3）：允许三次实际纠正；第三次成功继续，三次均失败后终态阻塞。首次诊断、重复 next/status/resume、上下文恢复与同一 attempt 重放不增加次数；同标识不同请求拒绝。
- [x] AC4（R4）：未知外部变化、根目录同名歧义、跨任务/仓库越界、软链、受保护文件漂移、损坏决策或证据不足不能静默放行；纠正写入失败不报告成功，重放不重复审计。
- [x] AC5（R5）：Check 文档自纠、fix/recheck、commit-repair、依赖及旧 runtime 兼容回归通过；同一次错误不被多入口重复扣预算，可纠正阶段不提前连带阻塞依赖任务。
- [x] AC6（R6）：相关源码、发布快照和部署协议一致，自动循环恢复实际执行纠正，不只显示“可重试”后结束对话；默认摘要能指向准确恢复动作，安装重复应用幂等。

## Out Of Scope

- 全部 blocked 无条件自动重试、任意路径猜测或一键接受所有当前变更。
- 自动撤销业务代码、重写提交历史、生产部署或修复原项目剩余业务验收问题。
- 重构整个 runner、增加通用任务执行引擎或改变普通任务的规划/提交授权流程。
