# 完善 GPT 专属提示词的限制与兜底判断

## Goal

让所有 GPT 模型获得同一套有依据的代码保护判断提示，减少任意限制、过度拒绝和掩盖失败的兜底，并保留必要的授权、身份、资料完整性及单次执行保护。

## Background

- 用户反复遇到固定容量/总时长门槛、无关日志字段或 ID 形状校验、跨机器画像匹配及失败操作阻塞升级等问题，要求研究并改进 GPT 专属提示词，随后明确要求开始本任务。
- 当前所有 GPT 共用 `src/assets/flower_session_start.py` 中的英文 `MODEL_WORKFLOW_HINT_BODY`。旧三个型号保留各自标签，其余合法 GPT 型号使用通用标签；模型名和外壳长度导致完整块字节数略有差异。
- 当前正文主要强调工作流、确认、模板和证据。限制、兜底及资源处理方式需要补充具体判断标准。
- 同题行为评估仍待执行。前期完成了真实任务/对话研究、官方资料核对及英文候选长度试算；工程注入和模型行为效果分别记证。

## Requirements

- **R1 共用内容**：所有合法 GPT 型号共用同一套新增工程规则，继承当前模型识别、标签、项目开关和事件分段合同。
- **R2 保护依据**：禁止为假想需求随意添加保护、容量门槛和静默兜底。新增或沿用的限制、兜底、超时和白名单须对应可核对的明确需求、具体故障证据、实测资源预算或依赖合同；核对保护对象、必要性及对用户目标的影响，保持足够解决问题的最小范围。
- **R3 规模与等待**：规模问题优先考虑流式、分批及有界并发；等待策略区分失联、停滞和持续推进。固定阈值的选择需要适用依据；单纯增大常量不能替代根因分析。
- **R4 最小必要校验与错误**：校验聚焦信任边界及实际决定需要的输入，附加字段按合同兼容处理。真实错误保持可见，兜底需具备清晰语义和恢复方式；身份、授权、资料完整性及单次执行等保护继续按适用合同生效。
- **R5 正反向验收**：提示同时要求核对危险输入的拒绝和正常输入的接受，覆盖大资料、长任务、版本差异及恢复场景，并检查相关入口和完整操作路径。
- **R6 兼容与预算**：保留现有工作流、确认、指令优先级及证据要求，完整模型提示块继续遵守现有 2048 UTF-8 字节预算；验证真实 SessionStart 输出及项目更新投影。
- **R7 评估证据**：形成从真实故障提炼的可复用案例及评分标准；自动化回归证明新增提示已正确生成与分发，模型行为改善需独立同题对照，交付时明确证据类别。

## Acceptance Criteria

- [x] **A1 → R1、R6**：旧三个型号及通用、版本后缀、未来 GPT 型号共享新增内容；非法、缺失、非 GPT、开关和跳过场景保持回归通过。
- [x] **A2 → R2—R5**：已审阅正文覆盖保护依据、规模处理、必要输入、错误可见、正反向验证及原有安全保护；归一模型名和标签后正文一致。
- [x] **A3 → R6**：完整提示及 SessionStart 分段实际测量通过既有预算门禁，原有工作流与确认要求继续由专项断言覆盖。
- [x] **A4 → R7**：案例至少覆盖 Git/文件总量、长任务、附加元数据、跨版本/硬件兼容、失败恢复衔接及真正危险输入，列出期望行为与评分项。
- [x] **A5 → R1、R6**：作者源、当前项目投影、Plugin ownership、README 和相关规范一致；原生 Ubuntu/Windows × Python 3.8/3.12 的受影响 CI 在对应业务提交上通过。

## Scope Boundaries

- 交付为 GPT 共用提示词、工程回归、评估案例及分发说明。各业务项目的具体限制整改由其任务或会话处理。
- 常规工程参数依实际合同、负载和资源选择；影响正常支持范围的未决取舍仍按现有规划规则收敛。
- 自动化测试与真实模型行为评估分别报告；提示词上线不等于已测得返工率或误拒绝率下降。
