# 拦截条件盘点

用户在初轮实现后明确要求删除不合时宜的限制，减少因未来日志格式和内容变化进入人工确认的情况。

## 删除或收窄

| 条件 | 决定与依据 |
| --- | --- |
| Claude 未知 user 日志字符串抛错 | 删除。未知附加记录不提供执行许可，必需来源由定位/claim 检查 |
| origin.kind 与 turnOrigin 双字段、平台差异 | 收敛为结构化主字段及旧字段回退。人工粘贴仍由 human 来源作废 |
| 针对 isMeta 的追加例外 | 随未知记录通用旁路删除，不积累每种元消息的特判 |
| Claude 通知须严格以固定 XML 外壳开始/结束 | 删除。提取唯一 task ID 后匹配本项目拥有的任务 |
| Codex 完整 wake_message 相等、恰好一个文本块 | 删除。保留稳定 Flower 请求标记与原生 clientId 匹配 |
| 原生回合、消息与 task ID 的 UUID/字符形状及单字段长度限制 | 删除。作为非空不透明字符串，资源预算由整体状态与日志层控制；自有 UUID 契约保留 |
| 原生日志文件名必须拼入 UUID 并固定后缀、ID 原始字节必须直接出现在 JSON 行内 | 删除。使用宿主提供的准确路径及解析后的身份，保留原目录范围、文件身份和会话归属 |
| Codex 最终回复全部内容块必须为同一种 Text 结构 | 删除。提取可用文本，实际冻结正文仍须完整展示 |
| 展示、领取各自 300 秒期限 | 删除。等待时间来自用户策略，时效由输入/材料/窗口/单次执行约束 |

## 保留

- 当前平台、会话、项目和原生回合归属。
- 请求冻结材料、实际完整展示和用户配置的倒计时。
- 新人工输入、回滚、日志身份/边界、原窗口失效。
- 状态锁、generation 竞争、准确 claim/started 及单次执行。
- 原生服务、同窗口归属、传输完整性和解析资源预算。

原生 Codex 只读样本包含 150 条普通消息，均有 client_id。仅依据 client_id 识别 Flower 通知会误判普通消息，因此仍需稳定请求标记。通知文字本身不参与授权。
