# 修复升级快照误扫运行时目录

## 目标

让包含本地运行时研究资料的项目正常执行 Flower 更新，并保持升级失败时的精确补偿语义。

## 背景与证据

- 用户报告 vibecoding-bench 从 beta.14 更新 beta.15 时，在 `.trellis/.runtime/criu-image-sharing-research/criu-4.2/CLAUDE.md` 触发受管软链错误；该文件为研究源码中的正常链接。
- 本会话已在隔离目录复现：`shouldExcludeFromBackup(".trellis/.runtime/")` 返回 false，`createUpdateSnapshot()` 进入研究目录并抛出同类错误。
- `src/lib/update-transaction.js:38` 仅复用 Trellis 的排除表，`:125` 在默认扫描中拒绝软链。Trellis 0.6.14 的排除表包含任务、规范、工作区等用户目录，缺少 `.runtime`。
- `src/commands/update.js:73` 只为跨版本预演创建沙箱，`:311` 只为真实更新创建恢复快照，因此同版本预演与真实更新经过不同路径。
- 用户明确要求修复后再发新版 beta。开发验收结束后续接项目发布 SOP。

## 需求

- **R1 默认扫描边界**：默认快照、沙箱和恢复遍历排除精确的 `.trellis/.runtime` 子树，运行时目录中的普通文件、研究源码、软链和特殊文件不参与默认受管扫描。
- **R2 精确受管目标**：Plugin 明确计划写入的路径继续使用现有 forcedScopes 机制精确补偿，覆盖运行时目录内显式受管文件及新建子树。
- **R3 数据保护**：运行时中的非目标资料、链接及既有父目录在真实更新、沙箱和失败恢复中保持；生命周期写入后的真实执行状态由原 owner 维护，补偿沿用当前状态；精确受管目标仍按原内容和 mode 恢复。
- **R4 校验边界**：明确受管目标及其祖先继续接受普通文件/目录和路径边界校验；相似目录名与其它受管目录继续执行原规则。
- **R5 兼容性**：保留现有 CLI 参数、快照 schema 和 Trellis 依赖版本。升级器只增加本地运行时目录的边界语义。

## 验收

- **AC1（R1/R5）**：带研究软链的隔离项目可创建默认快照及沙箱，manifest 和沙箱内容排除运行时用户数据，来源数据保持一致。
- **AC2（R1/R3）**：真实 Flower CLI 的同 Trellis 版本更新可经过快照并完成正常更新；预演与真实路径均覆盖该场景。
- **AC3（R1/R3）**：真实 CLI 在 Plugin replay 故障后恢复受管文件、版本和 mode，运行时资料、链接及生命周期完成后的当前执行状态保持。
- **AC4（R2/R3/R4）**：显式运行时目标可恢复旧内容并清除新增目标；已有父目录和非目标兄弟节点保留。受管目标或祖先为软链时正确拒绝。
- **AC5（R4/R5）**：近似目录名、普通受管软链、既有 spec 精确备份和外部 Plugin 目标回归通过。
- **AC6（R1—R5）**：本地完整回归及对应提交的 Ubuntu/Windows 原生 CI 通过，随后按发版 SOP生成新版 beta 的版本与 CHANGELOG 预览。

## 范围边界

- 本轮包含升级器、对应回归、可执行规范及后续 beta 发布承接。
- 业务项目的实际升级、研究源码整理、通用 Git ignore 策略、Trellis 依赖升级与已发布标签回写属于独立范围。
