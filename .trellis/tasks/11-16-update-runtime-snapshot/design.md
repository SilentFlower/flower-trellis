# 技术设计

## 默认扫描与明确写入目标

`createUpdateSnapshot()`、`createUpdateSandbox()`、`extendUpdateSnapshot()` 和 `restoreUpdateSnapshot()` 共用 `scanScopes()`。在该层按项目相对 POSIX 路径识别 `.trellis/.runtime` 及其后代，使用精确目录边界匹配。默认遍历在读取节点属性和进入目录前裁剪此范围，覆盖运行时根本身为链接、后代含研究链接或特殊文件的情况。

范围判定统一在节点属性检查之前执行，既有上游排除规则沿用这一顺序。补充的 `worktrees` 根链接回归已复现同类错误；本轮通过调整共同判定顺序解决，排除目录集合只新增精确运行时子树。

现有 `forcedScopes` 同时表达目标子树与通向目标的祖先。保持显式计划目标可被精确捕获和恢复；进入被默认排除的运行时祖先时，只沿目标路径继续。仅用于到达目标的既有祖先目录不进入新增路径删除集合，避免恢复时删除原本存在的空运行时父目录。显式目标为目录时沿用整棵目标子树的原补偿语义。

精确目标的路径祖先必须在读取目标前核对普通目录边界，防止默认排除后再通过精确路径跨过运行时链接祖先。明确受管软链和特殊文件继续使用原错误语义。通用 canonical hash、其它平台目录及上游排除表保持既有职责。

## 数据与版本兼容

使用现有 scopes、forcedScopes 和 entries 表达补偿范围；快照 schemaVersion 仍为 1。默认运行时用户资料留在原项目，升级沙箱按需要自行建立临时运行时。确认状态及进程执行事实属于运行时状态，补偿过程沿用操作发生后的真实状态，避免用旧快照覆盖当前执行事实。

同版本 dry-run 保持现有低写入预演方式，通过真实 CLI 回归覆盖实际快照路径；跨版本沙箱自动继承同一排除边界。Plugin 预检仍在事务写入前扩展同一快照。

## 验证与交付

使用现有 update-backups 测试夹具补默认扫描、沙箱、真实 CLI、故障补偿及 forcedScopes 边界。平台无关的普通运行时数据和遍历边界用例在两端执行；真实软链场景按原生权限条件记录原因，保留实际受管链接拒绝回归。

修复不更新业务项目。代码交付通过对应提交的原生 CI 后，按 release-and-publishing.md 生成下一 beta 预览并取得发布说明确认，再执行规范发布链。
