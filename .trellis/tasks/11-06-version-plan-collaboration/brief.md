# Brief — 版本规划与多人任务协作

## Goal

- 让版本规划直接指导多人及 Agent 协作，明确每个工作包的责任、交接、依赖和验收。

## Scope

- 修改 `trellis-plan-version`、`trellis-extract-prd`、`trellis-verify-task`，同步维护源、平台入口、快照和受管副本。
- 覆盖业务操作与结果到 Wave 的映射、拆分前团队约束、工作包交接、实际任务校验、人员变更与旧规划兼容。

## Non-Goals

- 不改参考项目，不新增协作调度器、任务状态或强制台账，不调整现有实施与提交审批。

## Technical Overview

- `plan-version` 输出责任和交接依据，`extract-prd` 继承到单 Task，`verify-task` 对照来源、实际任务及子任务检查缺口；复用现有任务字段和 Brief 结构。

## Context & Decisions

- 按用户确认，先从业务角色、起始条件、操作和可验收结果划分 Wave，再确定 Task 与分工；一个 Wave 可以包含围绕同一结果的多个操作。工程完成和真实业务验收分别判断。
- 分工取决于能力、投入、代码边界、契约和可验证输出；支持多人按职责协作及单负责人使用 Agent，避免按人员或技术层机械拆任务。
- 依赖分别说明何时可开工、可联调、可验收；明确谁提供、谁消费、谁负责集成验收。按用户要求以小时（h）区间估工时，区分人工投入、Agent 运行、等待和日历排期，计入共享容量、评审和联调成本。
- 保留需求原文、历史交付和已有证据，支持滚动细化及明确要求的全量建任务；从 Skill-Garden 0.6 源头修改。

## Risks

- 粒度规则需要同时识别合法技术分工和无独立交付的碎拆；旧规划缺少信息时应报告缺口，避免误判或编造事实。

## Acceptance

- 多人和 Agent 两种场景都能回答：谁做、交什么、谁接、何时联调、谁收口。
- 工时有小时区间和估算依据，不以人天倍率或任务日期差填造数字，缺少依据时注明待估及下一检查点。
- 能发现实际子任务碎拆、重复范围、共享冲突、容量重复和验收责任缺失，Task 完成不会自动关闭 Wave。
- 八类场景回放及规则专项、同步产物、上下文预算和输出模板检查通过。
