# Brief — 分离后台确认的回合来源与请求生命周期

## Goal

- 让 Codex、Claude 在同一唤醒回合连续替换确认时，可靠完成展示、计时与领取。

## Scope

- 两端的回合来源持久化、恢复与失效处理。
- 共享状态转换、隔离 CLI 回归和安装资产验证。

## Non-Goals

- 发版、外部项目升级、生产操作及默认等待时长调整。

## Technical Overview

- 在现有状态文件中独立保存当前回合来源，复用日志和宿主身份核验。
- 确认请求分别管理材料、计时器和执行回执。替换请求时保留有效来源。

## Context & Decisions

- 两端均已隔离复现取消后再次准备失败。
- 基于当前容量和 Windows 改动增量修复，保留状态及请求版本兼容。
- 用户后续明确要求收敛拦截条件：未知附加记录旁路，来源字段及通知文案兼容，原生 ID 保留自身格式，展示与领取取消固定 5 分钟期限。

## Risks

- 来源保存与新输入之间存在竞态，需要锁内复核。旧来源失效后须停止复用。

## Acceptance

- 两端内部唤醒后取消、连续替换及跨 CLI 进程恢复通过，最新确认能独立计时并领取。
- 人工输入、退出、日志漂移、伪造通知及旧回执的失效与单次执行回归通过。
- 完整本地回归和隔离安装检查通过，后续以匹配提交的原生跨平台 CI 验收。
