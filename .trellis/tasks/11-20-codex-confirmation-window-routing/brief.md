# Brief — 修复 Codex 内置窗口定位与混用后台确认

## Goal

- 让 Linux/WSL 下的 Codex 内置窗口和共享窗口在归属可核验时正常使用 Trellis 后台确认。

## Scope

- 内置窗口定位、原生队列唤醒、不同会话混用时的窗口归属核验，以及退出和输入后的旧请求失效。

## Non-Goals

- 原生 Windows 内置模式扩展、业务项目升级及发版由独立流程承接。

## Technical Overview

- 共享窗口通过现有 `codex_tui` 连接定位。内置窗口通过精确会话写锁、前台进程身份与 `pidfd` 定位。唤醒继续使用带请求 ID 的原生队列。

## Context & Decisions

- **【关键决定】只有核实额外窗口属于另一个会话且独立于本机共享服务时，才允许它与当前窗口同时使用。归属不明和同会话双开继续走人工确认。**
- **【重要限制】新增的自动确认路径要求 Linux/WSL 可观测原窗口并具备本机共享队列连接。缺少任一能力时使用人工确认。**

## Risks

- **【交付风险】已验证能定位截图窗口，跨进程唤醒目前在 `0.171.0` 通过。截图的混合版本、精确撤回和关闭竞态需通过完整原生验收。**

## Acceptance

- 内置窗口完整展示后能倒计时、唤醒原会话并领取一次。不同会话混用时共享窗口也能自动确认。
- 同会话双开、原窗口退出或提前输入时，旧许可无法执行。待处理的旧提醒按原生 ID 撤回，恢复后的新窗口独立准备。

## Next Step

- 用隔离的真实 Codex 建立混合版本原生回归，再接入窗口定位与核验。
