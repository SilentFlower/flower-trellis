# 原生 Codex 与 Claude 会话默认启用超时确认

## Goal

用户更新 Flower 后照常打开 Codex 或 Claude Code，走到 Trellis 已有的确认点即可看到本次等待时长，并按已展示的默认动作继续，无需改用 Flower 启动命令。

## Background

- `0.6.13-beta.2` 的项目策略已默认开启，但只有 `ftl session` 管理的会话可计时。`cc-runtime-bridge` 的 Codex 会话由共享 App Server 管理，Push 计划展示后退回手动确认；直接运行 `claude` 也没有接入该能力。
- [单窗口隔离实验](research/foreground-cli-results.md) 中，关闭 Codex 会话唯一的窗口后，共享 App Server 仍让普通工具等待到期，并把结果交给原回合。判断本次确认必须核验发起它的窗口。

## Requirements

- R1：只交付 `ftl confirm` 一套前台确认流程，覆盖原版 Codex 本机共享 App Server 和直接启动的原版 Claude Code。助手在确认点调用，用户无需手输或单独开启项目确认。共享 Codex 必须核验原连接，未接入保持人工。项目与单类关闭仍有效。
- R2：Brief 首次开工、Check-All 问题处置、Push 精确计划共用既有策略。只有用户在当前会话看到完整冻结材料、默认动作与本次等待时长后，才开始计时。无法核验该能力时明确说明并保持手动确认。
- R3：保留现有时长和默认动作。Brief 正文 1000 字内 100 秒，其后每 500 字加 30 秒且不足一档按一档，默认按本次 Brief 开工；检查首条 100 秒、每多一条加 30 秒，零条不等待，默认修复当前全部待处置项并重检；Push 固定 200 秒，按已展示的模式提交和推送，明确只提交时才仅做本地提交。
- R4：在自动动作开始前，用户先提交回复、取消或修改方案时，旧默认选择失效。关闭会话、当前客户端断开或宿主不能证明该会话仍可交互时取消未开始的动作。重开不会补跑；不能凭共享服务、线程记录或后台进程还在就继续。
- R5：同一份材料与范围只可领取一次；执行前复核所属会话、任务、正文及 Git 基线。区分人工回复、策略超时与取消。Spec 歧义、新业务取舍、风险接受和独立权限确认保留人工；自动循环沿用自身授权，不叠加计时。
- R6：两个原生日常入口都通过验收后，移除 `ftl session` 命令及其使用说明，不作为备用入口交付。升级保留已有 `confirmation_timeout` 配置，清理受管旧入口材料时保留用户配置与其它能力。

## Acceptance Criteria

- [ ] AC1（R1、R2）：通过未经修改的 Codex 客户端、共享 App Server 和普通 `claude`，由助手使用正式 `ftl confirm` 各完成一轮操作。确认内容先完整出现，随后显示本次时长，沉默到期后恰好继续一次。项目关闭、单类关闭、能力缺失均走有原因的手动分支。
- [ ] AC2（R3）：覆盖 Brief 1000/1001 字、检查 0/1/2 项、Push 200 秒，以及三个默认动作和 Push 两种模式；不因宿主预算不足缩短用户时长。
- [ ] AC3（R4、R5）：在两个实际入口分别验证人工提交、取消、窗口关闭、断开、重开、临界输入、变更材料、重复等待与领取。Codex 覆盖会话只有一个窗口和另有订阅者两种情况；共享服务保持在线，跨过原截止后旧事项不能领取或执行，且重开不能补跑。
- [ ] AC4（R5）：验证子会话、不同客户端或项目、材料或分支变化均不能领取原许可；已开始动作的结果据实记录。
- [ ] AC5（R6）：对含 beta.2 的隔离项目执行升级、重复更新和卸载，验证受管命令与文档移除、策略和用户自有文件保留、原生功能可用；验收证据区分普通使用入口和仅用于隔离的实验入口。

## Out of Scope

- 其它未验证的 Harness / 客户端 / 运行模式，改写独立权限审批，关闭后由守护进程或队列唤醒用户会话。
- 本任务不改等待策略的默认值与业务动作，也不将新功能自行用于本任务的开工、检查或提交授权。
- 不给 Codex 或 App Server 打补丁、重编宿主或替换用户运行中的程序；普通项目安装不改变现用共享连接或全局配置，不引入新启动器；本机见证按明确操作接入。
