# 项目内自定义超时确认与 Codex 输入验证

## Goal

在当前项目提供时长可自定义的后台确认计时，保持主对话可继续输入，到期可靠唤醒同一 Codex 会话，并让用户回复后的旧提醒失效且不重复执行默认动作。

## Background

- 用户要求先在本项目实现，再用自己的 Codex 观察效果；此前已排除固定约 120 秒的原生超时、独立网页或窗口、需要切换启动入口的方案。
- 用户随后明确选择后台终端方向，要求不阻塞对话，重点解决可靠唤醒与用户输入后的重复触发；此决定替代此前以前台等待和 Enter steering 为核心的技术候选。
- 脚本与二进制不改变客户端的输入投递能力。首版复用项目现有 Node.js 环境和已经安装的 WebSocket 实现，先验证交互效果，不把打包原生二进制作为试用前提。
- 当前 Flower 是 Node.js ESM CLI；本机 Codex 为 0.167.0，正常连接 managed daemon，工具环境提供精确的 `CODEX_THREAD_ID`。
- `research/managed-queue-result.json` 已记录：独立订阅连接能收到同一会话的用户消息；原生队列可唤醒空闲会话并删除待处理提醒。相同 `clientUserMessageId` 重复入队会产生两条记录，必须自行实现请求去重。
- 旧的前台等待、Stop hook 计时和原生表单实验不能直接证明本方案；首版不恢复见证代理或前台启动器。

## Requirements

- R1：确认等待时间由调用方显式指定；计时在后台终端运行，启动后立即返回，当前回合结束后用户可以正常继续对话。
- R2：用户留在当前 Codex 对话和终端内操作，不打开外部页面或窗口，不要求重新包装 Codex 启动入口或手工部署服务。
- R3：用户提交回复时立即使该会话旧的待确认请求失效；修改意见优先于旧默认动作。不将前台阻塞等待或依赖 Esc 取消作为主方案。
- R4：区分人工介入、正常到期、中断和执行失败。中断、失败或未知结果不得解释为自动批准。
- R5：等待程序只返回结果；真实任务开工、问题修复、提交或推送仍由调用方依据原授权范围决定，空答案或时间流逝本身不构成新的授权。
- R6：本轮首先服务当前项目的 Codex 试用，不以跨客户端通用、发版或替换客户端二进制作为通过条件。其它平台的能力不得从 Codex 探针结果推定。
- R7：后台到期后通过精确会话 ID 向原 Codex 会话发送唤醒事件，区分成功入队与实际唤醒；不得猜测“最新会话”，不得将只运行完后台程序冒充会话已经继续。
- R8：每次等待具有唯一请求标识。重复 worker、重复投递或迟到提醒不能重复消费请求；默认动作前必须重新核对请求仍有效且尚未消费。
- R9：用户回复先于提醒消费时，应取消尚未发送的提醒，并尽量撤回已经入队但尚未执行的旧提醒；与到期同时发生的竞态须有可观测、确定的处置。
- R10：首版只对用户明确发起的演练生效；默认结果为演练文本，不直接执行真实任务开工、修复、Git 或其它业务动作。
- R11：提供当前项目的试用、查询和取消入口。断开连接、目标会话不匹配、能力不支持或结果未知时停止自动继续，给出明确状态。

## Acceptance Criteria

- [x] AC1 / R1：至少两个不同的自定义时长能够按指定时间返回到期结果；非法参数立即失败。
- [x] AC2 / R1、R2：在正常启动的 Codex 中，通过原有命令工具启动后台计时后立即结束当前回合，无额外网页、窗口、MCP 注册或前台启动代理；等待期间用户可提交新消息。
- [x] AC3 / R3、R7：真实 Codex 0.167.0、用户实际使用的 managed daemon 路径下，分别验证无人回复时到期唤醒、用户提前回复时旧等待取消。
- [x] AC4 / R3、R4、R8、R9：验证重复 worker、重复唤醒、到期与用户回复竞争、提醒已入队后用户介入等情形，旧请求不能重复执行默认动作。
- [x] AC5 / R4、R5：取消或执行失败不执行演练默认动作；测试不真实修改任务状态、提交或推送。
- [x] AC6 / R6：保存可复现命令、真实客户端版本、配置和测试结果，明确本地实测与其它平台未验证的边界。
- [x] AC7 / R7：唤醒投递失败、客户端退出或回执未知必须记录明确状态，不静默报告成功，不向其它会话补投递。
- [x] AC8 / R10、R11：新的 Codex 会话读取本项目说明后，能按显式请求启动演练，并能查询或取消；未主动启用演练时现有人工确认流程不变。

## Non-Goals

- 不发布 npm 包、替换 Codex/Claude 客户端或部署后台常驻服务。
- 不将额外页面、窗口或 MCP 表单作为当前原界面要求的隐式替代。
- 不恢复已经回滚的整套见证、PTY 启动器和旧确认运行时。
- 本轮不自动启用日常 Brief、Check 或 Push 的超时默认授权；先提供当前项目可主动调用的试用入口。
- 不承诺其它客户端、Windows 原生 Codex 或无 managed daemon 模式已通过原生兼容验收。
