# Brief — 完善 GPT 专属提示词的限制与兜底判断

## Goal

- 让 GPT 编码时依据具体问题设计保护，减少任意限制、过度拒绝及掩盖失败的兜底。

## Scope

- 更新所有 GPT 共用的专属提示词。
- 补齐模型一致性、注入、开关、预算与兼容回归。
- 整理真实故障评估案例，同步说明、规范和项目投影。

## Non-Goals

- 各业务项目的具体限制整改由其现有任务或会话处理。

## Technical Overview

- 在 Flower 作者源的共用英文正文中补充工程选择规则，经原 SessionStart 和 Plugin 分发链交付。

## Context & Decisions

- **【关键决定】所有 GPT 共用同一套新增规则，限制、兜底和超时须有需求、具体故障、资源或依赖依据。**
- **【关键决定】规模与等待优先采用流式、分批及进展判断，验收同时检查正常场景完成和危险输入拒绝。**
- **【关键决定】身份、授权、资料完整性及单次执行等必要保护继续按实际合同生效。**
- 沿用现有模型标签、项目开关、事件边界和工作流要求，完整提示块保持在既有字节预算内。

## Risks

- **【交付风险】工程回归验证提示词已正确注入；生成代码的误拒绝是否减少，仍需独立同题对照评估。**

## Acceptance

- 新规则覆盖保护依据、规模处理、必要校验、错误可见及正反向验收。
- 各 GPT 归一后的正文一致，真实 Hook、预算、兼容矩阵及项目投影通过验证。
- 真实故障案例和评分标准可复用，工程证据与行为效果分开报告。
