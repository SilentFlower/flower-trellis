# 完善 Flower 团队克隆后的安装与版本记录

## Goal

让团队成员克隆项目后获得准确的 Flower 版本记录，并在缺少本机 CLI 时通过对话确认完成安装，避免忽略规则、过时记录和静默跳过导致功能不可用。

## Background

- 当前根项目旧 `.trellis/.flower-manifest.json` 为 `0.5.1`，现代锁和 state 为 `0.6.6`；旧文件可能误导缺少现代记录的团队克隆。
- `src/builtin-plugins/skill-garden/content-adapter.js:857` 读取旧 manifest，但迁移成功后不删除。
- `src/lib/manifest.js:413` 仍回退读取旧更新策略，直接删除可能丢失尚未迁出的偏好。
- `src/assets/flower_update_hook.py:43` 找不到 CLI 时返回空值，启动检查静默跳过。

## Requirements

- R1：执行 Flower 增强安装或升级时，目标根目录已有 `.gitignore` 就幂等调整规则，让 `.flower/plugins.json`、`.flower/plugin-lock.json` 和 `.flower/.gitignore` 可被普通 Git 操作发现；保留其他规则和注释，不自动暂存或提交。
- R2：`.flower` 保持根目录位置。状态、缓存、事务和个人设置继续作为本地数据；没有根 `.gitignore` 时不为此新建它，必要的本地忽略仍由 `.flower/.gitignore` 承担。
- R3：成功升级后删除旧 `.trellis/.flower-manifest.json` 文件，不再留下空壳或旧版本内容；仍需保留的更新策略和缓存应先迁入现代记录。升级失败时不得丢失原记录或策略。
- R4：旧项目仍可通过升级完成一次迁移。迁移前兼容读取服务旧项目识别，迁移完成后以现代声明和锁为依据。显式 `--no-enhance` 跳过增强迁移时，不提前删除旧项目的唯一记录。
- R5：已升级且提交相关文件后，现有 Codex/Claude SessionStart hook 在 CLI 缺失时输出安装引导；手动 `trellis-flower-update` 入口也能处理 CLI 缺失。
- R6：安装使用项目锁中可验证的 Flower 版本；安装后验证 CLI 可用并恢复当前请求，不隐式初始化、升级或覆盖项目文件。
- R7：项目版本无法可靠识别、缺少 Node/npm、权限或网络失败时，给出准确原因和可执行下一步，不声称安装或检查成功，不循环安装。
- R8：用户已确认安装体验：hook 只检测和提供上下文；助手先征得当前成员确认，再安装项目锁定版本，验证后继续原请求。成员拒绝后本次对话不重复追问，不自动提权或安装；依赖 CLI 的后续操作说明未满足的前提。

## Constraints / Non-Goals

- 本任务涵盖 Git 共享记录、旧记录退出和新成员安装引导这一完整协作流程；不迁移 `.flower` 目录，不发布 npm 版本，不改变全局 CLI 与项目内容版本的含义。
- 根项目已有的 `.flower/plugins.json`、`.flower/plugin-lock.json` 修改，以及 GitLab skill 和遥测任务文件均为本任务之前的变更，必须保留。
- 兼容正常升级、仅增强升级和 dry-run；预览不写目标目录，失败恢复新增改动涉及的文件。
- 自动首轮检测沿用现有 Codex/Claude hook 注册；不新增其他宿主事件，不承诺 hooks 被禁用或 Python 不可用时自动执行。其他平台可从手动升级入口触发检测。
- 不修改全局 Git 配置、不执行 `git add -f`，也不放开标准共享三文件以外的本地内容。

## Acceptance Criteria

- [ ] A1（R1/R2）：根规则为 `.flower/`、`/.flower/`、`.flower/*` 或通用隐藏文件规则时，共享三文件可被 Git 发现，局部规则不重新屏蔽它们，本地数据仍被忽略。
- [ ] A2（R1/R2）：重复升级无重复规则，保留无关规则和换行风格；根 `.gitignore` 缺失时不新建。
- [ ] A3（R3/R4）：旧策略和缓存迁移后仍生效，现代值优先，旧文件不存在；重放不恢复旧文件，未迁移旧项目仍能识别。
- [ ] A4（R3/R4）：新安装不生成旧文件；损坏配置、写入失败和补偿失败不伪装成功，能恢复的新增文件改动全部恢复，不能恢复时给出证据位置。
- [ ] A5（R1/R3/R4）：dry-run 不改忽略规则、不删除旧文件、不写配置、不安装 CLI；`--no-enhance` 不删除未经迁移的旧记录。
- [ ] A6（R5/R6/R8）：缺少 CLI 时输出可靠项目版本、安装命令、确认和验证要求；未确认不安装，拒绝后本次对话不循环提示。
- [ ] A7（R5/R7）：无有效锁、无 npm、CLI 不可执行、超时和异常输出有可区分结果，不误导重装；已安装 CLI 的更新检测和未知项目语义保持正确。
- [ ] A8（R1/R3/R5/R6）：隔离项目验证“升级、Git 共享、克隆后无本机 state/CLI、启动安装引导”链路，相关事务、迁移、平台分发及上下文门禁通过。
