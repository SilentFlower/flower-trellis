# Brief — 跨 Harness 确认点超时默认决策

## Goal

- 为 Brief、检查处置和提交计划提供可配置的超时默认选择，保证人工介入优先、退出取消与同一事项只执行一次。

## Scope

- 新增统一入口 `ftl session -- codex` / `ftl session -- claude`，接入一个 MCP 等待工具。
- 接入 Brief、Check-All、Push；增加项目与单类配置、请求状态、会话生命周期和审计。
- 完成 Flower CLI、Skill-Garden 作者源、安装更新保留及验证链的配套改动。

## Non-Goals

- 首版不开放其他 Harness 的自动模式，不为 Spec 歧义自动作答。
- 不在退出后唤醒会话，不恢复旧待决，不把超时记录成人工批准。

## Technical Overview

- 完整方案与默认动作展示且核验有效后，进入 MCP 等待；控制器统一处理计时、输入与退出。
- 人工输入先撤销再透传；到期返回策略结果，执行前再次核对材料并单次领取，随后进入原流程。
- 新会话使用新身份；失联、退出或范围变化使旧许可失效。模型侧只暴露一个短 wait 定义，不复制方案正文或每秒轮询。

## Context & Decisions

- Brief：1000字以内100秒，超出后每500字加30秒，不足一档按一档计算。
- 检查：首条问题100秒，每多一条加30秒；零条不等待。提交确认固定200秒。
- 接入有效时默认开启，支持项目级和单类关闭；无有效适配时保持人工。
- Brief默认按当前方案开工；检查默认修复当前全部待处置项并重检，新的业务取舍暂停。提交沿用有效计划的 commit + push，明确 commit-only 时才仅本地提交。
- Codex与Claude共用前台入口和MCP协议。Linux隔离普通TUI的11组实验通过，包含两平台200秒等待、人工撤销、受控关闭和强杀入口；模型响应均为本机mock。
- 持久改动落在Flower源码及 `vendor/skill-garden/.trellis/0.6/` 作者源，通过同步、compiled targets和生命周期安装交付。

## Risks

- 当前是研究探针，完整材料展示核验、领取前竞争、旧会话重开与真实流程尚需实现和测试。
- 真实终端HUP和原生Windows生命周期尚未验收；各运行模式通过验证后才启用自动策略。

## Acceptance

- 时间边界、独立开关、配置损坏回人工与更新保留均有验证。
- 两平台通过人工、超时、退出、重开、重复请求和竞争场景；已开始动作的退出结果如实区分完成、中断和待核验。
- 材料或Git基线变化拒绝旧许可，默认选择不扩大当前文件、分支或操作模式，仍执行原流程检查。
- 单工具与短结果保持小上下文；完成source、快照、安装更新一致性、本地完整回归及原生Ubuntu/Windows CI。

## Next Step
