Flower Trellis Beta 发版流程

本地把关版本与 CHANGELOG；推送 beta tag 后由 GitHub Actions 通过 npm OIDC 发布。

本地人工门禁

  • • 先 `npm run sync`，必要时提交 `enhancements/` 快照。
  • • 先执行 dry-run 并展示 CHANGELOG，确认后才能真实 release。
  • • 真实 release 只生成 bump、CHANGELOG、发布提交 和 tag。
  • • 本地 release 不执行 `npm publish`。

CI 发布边界

  • • `vX.Y.Z-beta.N` tag 触发 `release.yml`。
  • • CI 不拉 submodule，发布只依赖已提交的 `enhancements/` 快照。
  • • npm 使用 OIDC Trusted Publishing，无长期 token。
  • • beta 必须走 `npm publish --tag beta`。

阻断条件

  • • 未预览 CHANGELOG，不允许真实 release。
  • • `MANIFEST.sourceCommit` 与 submodule pin 不一致，先同步快照。
  • • 其他预发布 tag 不是 `-beta.`，CI 直接失败。
  • • npm Trusted Publisher 配置不匹配会导致发布失败。
