# 后台确认容量设计

## 快照与材料

Skill-Garden 的确认策略对仅需指纹的 Git 输出和普通文件分块计算 SHA-256。Git 快照保持现有命令参数和输出范围，短文本命令继续读取有界输出。进程应并发消费或隔离 stderr，期限到达时回收进程并返回仓库、命令和阶段；跨平台实现不依赖仅适用于 POSIX 管道的轮询。仍检查文件种类、路径、软链及读取期间的漂移。语义和身份字段继续参与冻结；摘要编码如有变化，明确与旧快照的兼容边界。

将需要完整解析或展示的材料与仅需哈希的载荷分开。配置、任务 JSON、展示正文等保留各自必要的有界解析；测量状态中重复存放的正文和快照，优先减小重复载荷。现有状态合同保持兼容，若必须调整格式，由升级取消旧请求后切换。

## 会话日志

在 Flower 的 Codex 和 Claude 适配器按文件身份、已核验偏移和未完成行续读。首读可扫描现有记录，只保留有限的近期证据与必需的身份/来源摘要。处理单条大型无关事件时，先区分事件类型；无法可靠分类且可能影响当前回合的记录保持人工。替换、截断或身份异常使相关缓存失效，禁止借用旧消息来源继续执行。

## 执行预算

区分 Git 命令、整轮策略、结构化材料、结果和状态预算。先记录代表性单仓、多仓及长会话基线，按有效负载和最慢阶段确定保留的预算；无依据的整份大小门槛按 R1/R2 移除。等待展示和唤醒后领取分别由生命周期控制，独立测试其过期边界。用户配置的倒计时和请求过期语义保持原样。

## 分发与回退

策略在 Skill-Garden 作者源维护；Flower Python 运行时在 `src/assets` 维护。同步随包快照和 dogfood，并走现有项目更新事务。回滚恢复整组资产；已取消的请求保持失效。
