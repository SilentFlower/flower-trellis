# Brief — 以输入事件序号统一 Claude 与 Codex 自动确认

## Goal

- 让 Claude、Codex 在普通回合、子代理回传后的主会话及恢复回合中，通过当前输入事件序号正常准备自动确认。

## Scope

- 两端宿主事件接入、共享状态机和输入序号契约。
- 准备、等待、派发、领取及 started 的新输入取消与竞争处理。
- 旧请求迁移、跨进程续接、分发协议、回归测试和项目规范。

## Non-Goals

- 本轮不调整人工风险接受策略、Git 停止条件和倒计时配置。
- 外部业务项目升级、软件发版和生产部署由后续流程承接。

## Technical Overview

- 准备时冻结当前会话、回合和输入序号；真实用户输入或中断使旧许可失效；完整展示后计时，到期按精确请求领取并记录单次执行。

## Context & Decisions

- **【关键决定】两端取消历史真实人工消息 ID 的准备门槛，子代理回传后的主会话纳入正常路径。**
- **【关键决定】输入序号、当前回合和执行许可分别管理，保留完整展示、原窗口绑定及单次执行。**
- 已从现场日志复现 peer 来源导致准备失败，日志约 1.8 MiB。
- 确认资产升级沿用旧等待失效机制；已开始动作按实际结果记账。

## Risks

- **【交付风险】漏记新输入或误认内部通知会放行旧许可，须覆盖各竞争位置和真实宿主事件。**

## Acceptance

- Claude、Codex 通过当前输入序号完成准备；Claude 的 peer 回传场景完成自动确认链路。
- 新用户输入或中断在准备、展示、等待、派发、领取及 started 前均使旧许可失效。
- 原窗口退出、材料变化、人工粘贴提醒、重复领取和重复执行按现有契约处理。
- 取消重建、旧状态迁移和跨进程续接通过验证；收集两端原生验收及匹配提交的跨平台 CI 证据。

## Next Step

- Brief 确认后激活任务，进入实现路由，先补现场 peer 回合与缺少历史人工消息 ID 的回归用例。
