# `ftl confirm` 前台限时确认设计

## 交互与边界

交付只保留一个前台确认流程。两端把各自的原窗口证据交给同一个 `ftl confirm`，共用材料、时钟、取消及单次领取规则。

助手在 Brief、Check-All 或 Push 的原确认点调用普通 CLI。`ftl confirm status` 检查宿主与策略；`ftl confirm prepare` 从 stdin 读取 spec，返回冻结正文、时长及请求 ID；助手在当前原生对话完整输出该材料，再调用 `ftl confirm <id>`。后者在同一前台命令内复核展示、等待、再次复核并单次领取；动作仍由原流程执行。`ftl confirm finish <id> <outcome>` 只记录真实结果。现有时长、Git 范围、权限、人工与 auto-loop 语义不变。没有逐秒 stdout 可见性依赖。

准备复用 Python 材料与 Git 快照，写入只含 spec、版本及原交互绑定的临时记录。等待与领取分别去重；每次复核原窗口和同一份材料，改变/取消后不能重跑同版本。活许可不写入可恢复队列，持久记录只用作材料、去重和审计。

## 原版宿主

- Codex 0.167.0：原版工具的 `CODEX_TOOL_CALL_ID` 匹配 App Server 命令事件。Unix 见证器以真实连接、用户回合与工具为归属；原窗口断开、人工输入、中断及重开使旧绑定无效，领取前用同一真实连接的 WebSocket ping 复查。已核验正文的原窗口断开时，通过原上游连接中断旧回合，等待回执后关闭转发。见证记录先传到原窗口的完整助手正文摘要，确认不依赖工具 PTY 或共享服务是否活着。沙箱不能连见证套接字，因此使用项目 gitignored 文件挑战与签名回复；密钥只在见证器内存，公钥从用户配置读取。普通安装不改共享入口；显式本机接入后日常仍用原命令。缺少见证保持人工。
- Claude Code：正常项目设置加入本项目生命周期 Hook，识别真实原终端进程、主会话、人工输入版本及相符 Bash 调用。根据同一条助手消息的原生转录证明展示；缺少绑定或正文则人工。保留用户原有 Hook、MCP 和权限。

隔离的原版终端覆盖实际三个门禁、两种 Git 模式、默认 200 秒等待、关窗及 beta.2 迁移。共享 Codex 同时验证会话只有一个窗口、另有订阅者两种情况。验证记录统一见[前台命令验证](research/foreground-cli-results.md)。
