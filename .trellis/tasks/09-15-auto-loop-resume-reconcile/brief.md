# Brief — 补齐 Auto-Loop 恢复阶段的三轮自动自纠

## Goal

- 路径登记或上下文恢复遇到可纠正错误时，自动诊断、改正、复核并续跑，首次错误不直接结束队列。

## Scope

- 新增任务文档参数 `--task-file` 和登记预检，保留既有 `--file` 的仓库路径语义。
- 恢复时保留原 action、文档基线、待回写决策、检查深度和路由；正确登记的修改可继续实施。
- 增加 action 内 `reconcile` 纠正入口、三轮实际尝试预算及幂等回执，覆盖旧错误路径的有证据修正。
- 同步 runner、Auto-Loop/相关恢复指引、测试、规范、发布快照及受管安装副本。

## Non-Goals

- 不把所有 blocked 自动放行，不自动接受未知外部修改，不重构整个 runner。
- 不修改原项目历史 run、不撤销业务代码或提交，不执行发布、部署或归档。

## Key Decisions

- 首次诊断不计次；查询、上下文恢复和同一尝试重放不扣次数。第三次纠正成功可继续，第三次仍失败才终态阻塞。
- agent 根据原决策和真实差异纠正，runner 独立校验；路径修正只能精确对应当前任务文档，原错误记录保留。
- 纠正不代表业务完成，仍由原 action 的真实 `record` 推进阶段和更新文档基准。
- 保留既有 Check、实现重检和提交修复预算；同一次错误只能进入一个通道，可纠正阶段不连带阻塞依赖任务。

## Key Context

- 依据 9 月 13 日 `xhgj-ai-harness-poc` 的真实事故；当前 runner 存在错路径登记未拦截、next 提前阻塞及重复获取检查基线三个相关缺口。
- 作者源是 `vendor/skill-garden/.trellis/0.6`；测试复用 Flower 的 Python CLI fixture 与恢复协议测试，schema 2 仅增可选字段，持久状态保持 running。

## Risks / Deferred

- 根目录同名歧义、越界、软链、受保护文件、损坏决策或无法归因的变化仍阻塞；审计与状态写入失败必须可安全重放。
- 已终态的历史 run 仍需显式恢复；缺可信基线的旧 runtime 不猜测放行，schema 1 保持原协议。

## Acceptance

- 复现旧错路径及正确登记后压缩恢复两条链，自动继续原 action，无需人工 retry-blocked 或虚报实现完成。
- 覆盖三轮成功/耗尽、重复查询零计数、回执丢失重放及原检查基线不变。
- 越界和未知修改不能静默放行；现有检查、提交、依赖、路由及旧 runtime 回归通过。
- 恢复指令让 agent 同轮完成纠正；源码与投影一致，隔离安装重复应用幂等。
