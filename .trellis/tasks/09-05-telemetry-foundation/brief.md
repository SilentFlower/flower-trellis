# Brief — 遥测第一批：平台活跃与核心操作质量

## Goal

- 让管理员了解 Flower 的实际使用平台、持续使用情况及核心操作质量。

## Scope

- **flower-trellis**：Claude Code/Codex 的 0.6 full hook 日活动；初始化、项目升级、自更新、插件安装的结果、错误分类与耗时；本地去重、有限队列、独立发送及只读诊断。
- **ai-fund**：新增事件接收与管理员统计接口、D1 事件/日活动/首次观测记录、清理和设备删除一致性；现有安装监控增加使用概览、平台与版本、持续使用、操作质量四区。
- 本轮实施包含两仓本地代码、迁移文件、测试与文档。

## Non-Goals

- 其他 AI 平台及 old/0.5 的新会话 hook、任务流转、Skill 调用、真实人数和在线时长统计；不采集对话、源码、路径、原始错误等业务内容。
- 生产数据库执行、部署、发版、提交推送另按各自流程处理。

## Key Decisions

- 两类事件：按安装/UTC 日/平台去重的活动，以及一次外部操作的唯一终态；CLI 单列，嵌套操作和网络重试不重复计数。
- 保留旧接口，新指标只用 v2；复用随机安装 ID 和现有总开关，开发者别名可空。关闭和采集失败不改变命令输出/退出码，主流程不等待网络。
- 本地队列最多 200 条、补传窗口 72 小时；服务端事实保留 180 天，首次观测记录保留到设备删除。
- 回访为首次观测后 7/30 日内再次活动，窗口加补传宽限后才成熟。成功率排除取消和未知终态；纯执行耗时与包含交互等待的耗时分开。

## Key Context

- Flower 采集入口在 `src/lib/telemetry.js`、命令编排和自有 `src/assets`/平台 Patch；不直接修改已部署 hook 作为发布源。
- ai-fund 沿用 Worker/D1 和 Vue 管理端，复用当前角色鉴权；先准备兼容的新接收服务，再接入新客户端。

## Risks / Deferred

- 强杀、离线、关闭遥测或未接入入口会产生观测缺口；旧数据不能还原历史日活。Windows 独立发送进程已通过原生平台专项验证，见 [检查报告](check-report.md)。

## Acceptance

- 平台归属、跨日活动、回访和质量指标可通过固定样例复现；零样本与未成熟队列有明确空态。
- 新旧客户端兼容；并发重试不重复计数；关闭、损坏状态、超时与限频不影响主流程。
- 管理员权限、事实清理和设备删除一致；两仓测试及隔离的采集→接收→数据库→页面验证通过。

## Next Step

- 完整 Brief 已获确认，子任务本地实施与检查完成；下一步准备两仓提交计划，生产迁移与上线另行执行。
