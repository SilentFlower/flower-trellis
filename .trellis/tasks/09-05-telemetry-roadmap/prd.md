# Flower 遥测产品洞察路线图

## Goal

把 Flower 遥测从安装与版本统计扩展为可指导产品改进的使用洞察，按收益和采集可信度分批建设。用户已要求建立 roadmap，并优先规划第一批。

## Requirements

- R1：第一批包含实际使用平台、可观测活跃与回访、初始化/升级/插件安装结果。
- R2：第二批包含任务创建、启动、完成，观察工作流采用情况。
- R3：后续验证少量核心 Skill 的实际调用，再扩展高级功能使用统计；不把安装量当调用量。
- R4：每批均明确数据来源、指标定义、覆盖限制、验收标准和依赖，后续批次不自动进入实施。
- R5：延续用户级遥测开关、普通运行静默、数据白名单和管理员可见的边界。

## Task Map

| 批次 | 交付物 | 任务 |
| --- | --- | --- |
| 第一批 | 平台活跃与核心操作质量 | [telemetry-foundation](../09-05-telemetry-foundation/prd.md) |
| 第二批 | 任务流程采用与流转 | 后续规划时创建子任务 |
| 第三批 | 核心 Skill 调用与高级功能采纳 | 完成观测可行性验证后创建子任务 |

路线图以 [roadmap.md](roadmap.md) 为优先级与批次依赖的入口；本父任务不直接承接产品实现。

## Acceptance Criteria

- [x] 路线图覆盖本次讨论的三个批次，并标明当前状态。
- [x] 第一批方案可回答使用平台、持续使用情况和核心操作质量三个问题。
- [x] 后续批次复用第一批的身份、事件和指标定义，不重复计算相同活动。
- [x] 每批保留独立验收和回退边界；总体统计可解释观测缺口。

## Out Of Scope

- 本父任务维护路线图；第一批产品实现由子任务独立承接，发版和生产数据库执行、部署另行处理。
- 后续批次不预设日期承诺或自动开始。
