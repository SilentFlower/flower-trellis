# 统一 Claude 与 Codex 自动确认的会话读取边界

## 目标

让 Claude 与 Codex 的自动确认只关注当前回合和本次等待期间的事件。此前用户说过什么、代理回传了什么，都不影响本次准备。

## 背景

已用 `cnooc-virtual-mall-data` 的 Claude Code 2.1.293 原会话复现。当前实现从头扫描会话记录建立人工输入基线，遇到第 171 行的 `peer/peer` 代理回传便转人工。第 184 行还有一种仅落日志的通知：`origin.kind=task-notification`、`queueTranscriptOnly=true`、无 `turnOrigin`。原判定见 `src/assets/flower_confirmation_runtime/claude.py:209` 和 `:230`。

Codex 原实现也从头读 rollout，旧的损坏记录或已知事件字段变化可能阻断新确认。当前会话已观察到 `task_started` 先于同回合的原生 `UserMessage`。

## 需求

- R1：准备只核对当前回合并记录本次观察起点。此前消息的正文和来源格式不作为本次准备条件。
- R2：观察起点之后，真实人工新输入使旧等待失效。只有与本次请求、原生后台任务和当前回合匹配的真实通知可用于领取。明确的代理回传及仅落日志通知不参与判定。影响本次判断的来源歧义保持人工回退。
- R3：修复只交付到 `flower-trellis` 仓库内的作者源和本地投影。原项目会话仅用于只读回放。

## 验收

- A1（R1）：原会话的两种旧记录以及未知旧来源均不会阻断准备。Codex 的旧畸形事件也不会影响准备。两端当前回合证据缺失时回退人工。
- A2（R2）：准备期间和等待后的新输入均可使旧请求失效。人工粘贴通知样式仍算人工输入；真实通知可领取；其他任务、旧通知和仅落日志的通知无法领取。重新打开客户端后仍从同一本次边界观察。记录替换、截断、Codex 回滚或相关字段冲突保持安全回退。
- A3（R3）：作者源、本仓脚本和契约一致。只读回放原会话验证修复。

## 范围外

计时政策、授权协议改版、软件包发布及更新其他项目。
