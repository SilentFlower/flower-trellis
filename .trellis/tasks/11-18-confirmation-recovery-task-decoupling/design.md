# 后台确认恢复与任务声明设计

## 目标与边界

本任务统一处理后台确认的恢复输入、任务声明和会话身份三处契约。执行许可继续归属当前原生会话、完整展示的材料及单次回执。一个任务交付三项相互关联的修正，共用安装同步和确认链路回归。

## 任务声明

- Brief、Check、Push 均以材料中的 `task` 作为本次确认目标。移除 `material.task == active.task_path` 的准入条件。
- Brief 继续要求有效的任务目录及完整 Brief；Check/Push 允许 `task=null`，声明具体任务时核对路径和读取对应材料。
- 将当前会话绑定作为独立的冻结事实保存。它可以在准备时与目标不同；等待期间的变化仍沿用快照作废规则。
- 正文、findings、版本、Git 精确计划、任务材料和策略继续进入原有摘要。领取后的业务上下文返回显式材料目标。
- 更新 `confirmation.md` 与规范，清除旧的材料和绑定必须相等表述。

## Codex 原生恢复

- 从精确会话日志中的当前 `task_started` 读取 `turn_attribution` 与 `root_turn_id`，识别真实 `daemon_recovery`。
- 沿同会话的原生恢复关联定位被续接回合的输入锚点，保留输入来源回合与当前展示回合的区别。
- 来源记录绑定当前准备回合、原生输入、恢复关联及日志边界；沿用现有可持久化 `turnOrigin` 结构并在必要时扩展验证字段。
- 正常人工回合和原生队列唤醒继续沿用各自输入规则。系统恢复提示正文只作上下文，原生日志的结构化关联作为恢复依据。
- 从原始输入后的日志边界读取至当前准备，处理关联恢复及准备前插话；准备后的新输入和日志回滚继续使请求失效。
- 对缺失、跨线程、自引用或无法定位的恢复关联返回具体诊断；新确认继续完整展示并重新计时。
- 原窗口结束后的旧等待仍按现有生命周期失效。恢复支持作用于当前有效窗口准备的新请求。

## 会话身份

- 保留显式 `TRELLIS_CONTEXT_ID`、原生 Hook 会话与显式平台参数的优先语义。
- 默认命令通过当前宿主的明确上下文或实际进程身份选择平台，再读取该平台会话变量；移除多个候选时靠固定列表先后顺序选中的行为。
- 实现场景必须覆盖 Codex shell 中的当前线程标识与继承 Claude 标识共存。宿主证据须按 Linux/WSL 与原生 Windows 各自支持的进程接口验证。
- 只有一个平台候选时沿用原有普通命令行为。多个候选且宿主身份仍有歧义时输出明确诊断和显式上下文提示。
- 当前错误绑定记录保留归属；当前 Codex 后续激活和查询使用自己的会话记录。业务项目的现场升级另行执行。

## 源码与分发

- 确认适配器修改 `src/assets/flower_confirmation_runtime/`。
- 策略、协议和公共身份 Patch 修改 `vendor/skill-garden/.trellis/0.6/`，按照当前完整目标构造准确 selector/content。
- 执行快照同步、编译产物刷新与冲突检查，再通过 Flower 生命周期刷新本仓 dogfood。
- 保持 Python 3.8 基线，复用现有标准库进程与日志工具。

## 风险与回退

- 恢复输入与展示回合分离可能影响来源复用、正文定位和后续插话识别，需要跨进程续读回归。
- 材料任务成为范围依据后，材料生成方承担目标准确性；路径、内容和最终展示仍参与核验。
- 共享身份解析会影响任务和路由，需覆盖显式身份、单候选、多候选和反向继承场景。
- 按源、快照、Patch 编译层及 dogfood 同批回退；实际任务和用户会话记录保留。

## 日志追加的元数据时序

- 并发复验显示只执行追加的原生日志会短暂出现 mtime 已变化、size 仍等于上次观察值的状态，触发同大小重写保护。
- 仅在同大小且 mtime 变化时做有界元数据重读。只有随后确认文件增长且文件身份、已消费边界核验继续通过时，才按追加读取。
- 同大小持久重写、替换、截断及边界漂移继续失败。元数据重读预算固定 50 ms；定位、续读和读取后核验共用同一规则。
- 用确定性的 stat 时序回归覆盖追加瞬态、持续同大小重写和替换，并以真实跨进程并发回归验证。
