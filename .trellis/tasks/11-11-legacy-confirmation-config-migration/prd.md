# 升级时清理旧自动确认项目配置

## Goal

让已安装 Flower 的项目在升级时清除可确认属于废弃自动确认方案的配置，保留项目自定义配置和当前原生确认能力。

## Background

旧方案曾通过临时启动参数、Claude 确认插件、项目 Hook、项目脚本以及旧 CLI 实现限时确认。升级流程需要处理留在项目中并可核验归属的遗留配置或资产。

## Requirements

- R1：项目级升级自动清理已证实属于旧方案的 Codex/Claude MCP 条目及配套引用，有证据配对的旧 Claude 确认插件与 marketplace 注册、已退役的 Claude CLI 确认 Hook 与项目脚本。对沿用路径的后台确认资产，核对既有升级能否替换旧实现并保留现用 Hook。
- R2：配置匹配需同时核对名称和历史入口或注册结构。退役脚本需匹配已知内容或具备明确的旧受管证据。保留同名但来源不符、字段有歧义、格式异常或用户自定义的内容。保留现行原生确认 Hook、`codex_tui` 和 `confirmation_timeout`。
- R3：复用升级预览和事务。预览展示可清理项且保持只读；实际升级应用精确迁移，可通过现有事务恢复；重复升级不再产生清理变更。输出只显示项目相对路径和条目名。

## Acceptance Criteria

- [ ] AC1（R1）：历史签名正例在一次升级后移除旧 MCP 及其匹配的配套项，旧 Claude 插件和 marketplace 成对移除；已知旧 CLI Hook 与退役脚本移除；沿用路径的旧实现升级到当前项目内 Python 运行时。
- [ ] AC2（R2）：同文件中的自定义 MCP、插件、Hook、权限、原生确认设置保留；同名近似项、探针注册、格式异常和软链接保持原样；缺少配置时不新建配置；用户改过的退役脚本与自定义 Hook 保留。
- [ ] AC3（R3）：预演零写入；实际升级与平台 Patch 一同提交；验证写入失败的回滚；第二次升级零迁移变更。覆盖 Ubuntu 与 Windows 对应安装回归。

## Out of Scope

- 批量改写本机其他仓库、用户级配置、历史备份或运行时证据；全局旧 CLI 安装、临时启动参数和已退出的后台进程。
- 清理仅凭名称推测归属的注册，或改变现行确认策略和 Push 门禁。
