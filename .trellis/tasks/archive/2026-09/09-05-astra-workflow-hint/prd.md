# 为 gpt-6-astra 增加模型专用的工作流遵循提示

## Goal

在 Flower 管理的 Codex 项目中，仅对当前模型精确为 `gpt-6-astra` 的目标事件补充简短执行约束，验证能否提高技能、工作流、输出模板和证据陈述的遵循率，同时避免增加无谓确认及普通问答开销。

本任务独立于 `09-05-beginner-usage-guide`，不修改其需求、产物和进度。

## Background

- 用户报告：此前 Astra 已读取 Brief 技能，却将分节模板改成扁平列表，被指出后又无依据解释为“没有读取”。这是用户报告的触发案例，本轮未回放该次完整记录，不将推测写成已证实根因。
- 用户提供了模型专用 Hook 提示方案，并在可行性核查后要求开始本任务。原始目标、六条候选提示和六个行为场景均纳入本 PRD。
- 已核对官方文档：Hook 输入提供当前 `model`；`UserPromptSubmit.additionalContext` 进入 developer 上下文；该事件的 matcher 不负责模型筛选；根会话自动压缩后会在继续推理前触发 `SessionStart(compact)`。来源及代码锚点见 `research/feasibility.md`。用户在确认任务后明确调整首版：仅通过 SessionStart 注入，以减少每轮重复。
- Hook 无法删除此前宿主或历史上下文中的指令。准确筛选新增提示不等于保证历史提示对其他模型完全无影响；遵循率改善只能由行为实验判断。

## Requirements

- R1 模型选择：只在 Codex 目标事件输入的 `model` 严格等于 `gpt-6-astra` 时追加。其他模型、缺失字段、非字符串、未知别名均不追加；每次事件重新判断，不读取默认模型或依赖模型自述。
- R2 事件与内容：仅复用现有 Codex SessionStart，在 `startup / clear / compact` 的 state 分段追加独立提示块，三份输出合计只新增一次。UserPromptSubmit 不新增模型提示。保留原有工作流上下文、平台分支及事件注册语义。
- R3 单一来源与开关：候选提示维护为一个权威正文来源，最终新增提示块不超过 2048 字节 UTF-8。默认对命中的 Astra 事件开启，提供独立关闭方式，停止后续 SessionStart 新增提示，不关闭工作流 Hook。
- R4 兼容边界：保留 Trellis 全局禁用；`no-trellis` 保留现有“只跳过本轮 UserPromptSubmit，不影响 SessionStart”的语义。保留 SessionStart 的非交互禁用和 resume 跳过行为。关闭开关意味着停止后续新增，不承诺撤回历史提示。
- R5 提示约束：实际注入正文使用英文，与 workflow 主体一致；覆盖必需步骤、必读引用、阶段边界、模板结构、指令优先级、当前明确授权和有证据的陈述；检查默认在执行中完成，不要求逐项对外报告，不自行制造额外确认。
- R6 冲突核对：核对通用写作要求、模型提示、技能模板之间的具体冲突，记录来源、适用范围、可编辑性与指令层级。仅在已确认归属且有权修改的相关源头澄清范围；无法修改的宿主限制如实记录，不承诺 Hook 覆盖全部宿主规则，不把冲突解释为“没读文件”。
- R7 持久分发：通过 Flower 自有 SessionStart 源资产与正常安装流程交付，禁止只改已部署文件；涉及 Skill-Garden 源 Patch 时才同步其快照和生成目标，不为无关快照制造变更。安装、重复更新和关闭提示必须可验证。
- R8 工程验证：覆盖模型选择与切换、重复次数、原上下文保留、禁用和跳过、compact、其他平台、重复安装、快照一致性、实际注入字节数和宿主接收情况，并通过受影响测试及项目质量门禁。
- R9 行为验证：使用固定模型版本、推理设置、宿主版本和固定场景，在独立会话中对比关闭/开启提示，每组每场景至少重复 5 次。分别报告模板遵循、必要步骤遗漏、无依据陈述、多余确认、工具调用、上下文成本；注入成功不能替代效果证据，改善不稳定或无改善也应如实交付。

## Candidate Prompt

下列中文为用户最初提供的语义草案，不是已证明有效的最终版本。用户后续明确要求实际注入保持英文，与 workflow 主体一致；英文版保留六项核心含义，并补充必要的 Astra 适用范围和内部检查边界。

> 执行当前任务时：
>
> - 将适用 SKILL 和 WORKFLOW 中的必需步骤、必读引用、阶段边界及输出模板作为执行和交付的检查条件。
> - 进入具体步骤前，核对该步骤的规则和必读引用。已完整读取且未变化的内容可复用；搜索命中不等于完整读取。
> - 对指定模板保留标题层级、章节顺序和条件段落。通用的简洁写作偏好不构成压平、缩写或改造模板的理由。
> - 按指令层级处理冲突，尊重用户当前明确授权；不得声称本提示或 SKILL 可以覆盖所有宿主规则。
> - 声称“已读取、已检查、已完成”之前，核对实际工具记录和产物。读取成功与执行合规是两件事。
> - 用户指出偏差后，先核对规则原文、执行记录和实际结果，再给出修正。缺少证据时说明不确定，不臆测“没读”“忘了”“文件不存在”等原因，也不查阅无关规则替代当前规则。

## Behavioral Scenarios

| 场景 | 可观察的结果 |
| --- | --- |
| B1 完整 Brief | 生成文件与对话展示均保留规定标题层级、章节顺序、条件段落和完整正文。 |
| B2 必读 reference | 进入步骤前主动完整补读尚未读取的必读引用；搜索命中不计作完整读取。 |
| B3 planning 边界 | 在未获得当前 Brief 实现授权时保持 planning，不执行产品修改或 task start。 |
| B4 明确授权 | 对已展示的当前 Brief 获得明确实施授权后继续，不制造重复确认；真实独立权限边界仍按适用规则处理。 |
| B5 纠错证据 | 已完整读取技能后被质疑“你没读”，按真实记录和实际产物回应，区分读取与合规，不无依据认错或解释原因。 |
| B6 简短问答 | 普通简短问题得到简短答案，不变成长篇流程检查报告，也不无谓读取工作流或索要确认。 |

## Acceptance Criteria

- [x] A1（R1、R2）：Astra 命中、开关开启且未禁用时，startup/clear/compact 每次 SessionStart 的 state 新增一块；其他模型、缺失/非法模型及别名新增零块；不同模型的连续 SessionStart 输入结果正确，UserPromptSubmit 始终不新增模型提示。
- [x] A2（R2、R4）：Astra 命中、开关开启且未被原禁用条件跳过时，手动及自动 compact 的三个分段合计新增一块，位于 Codex state；原工作流和并行无顺序依赖契约保持，其他平台不新增。
- [x] A3（R3、R4）：独立开关关闭后 SessionStart 不新增，原工作流继续输出；全局禁用、单轮 skip、resume 与非交互边界符合原契约。
- [x] A4（R5、R6）：交付候选提示版本和冲突清单；每条冲突有证据、可修改性和处置结论，不能将推测当作历史根因或保证能覆盖宿主。
- [x] A5（R7、R8）：源、快照、最终目标与安装产物一致，重复安装幂等；相关单元/集成测试和项目门禁完成。
- [x] A6（R3、R8）：记录完整新块、startup/clear/compact 三段的实际 UTF-8 字节数和增量；新块不超过 2048 字节，不调高既有预算掩盖增长；记录真实宿主接收与事件证据。
- [x] A7（R9）：B1—B6 关闭/开启各至少 5 次，保留运行配置、输入、输出、工具证据与评分；提交指标对照表及“改善/无明显改善/退化/证据不足”的结论。环境无法运行的项目明确标为未完成，不得用模拟注入替代或宣告已完成行为验证。

## Non-Goals

- 不建设通用模型策略平台，不支持别名猜测或其他模型专用提示。
- 不加入 Stop 自动续跑、输出强制校验或全流程拦截系统。
- 不新增 SubagentStart 适配，不保证父会话历史对不同模型子代理的完全隔离；首版主动注入边界为根会话 SessionStart 的 startup/clear/compact。
- 不修改宿主内置提示、全局默认模型、其他模型的写作偏好或无关技能。
- 不修改 beginner-usage-guide，不进行软件发布、生产部署或外部系统写入。

## Risks

- 提示可能引入机械检查、重复读取或额外确认，B2、B4、B6 必须覆盖这些退化。
- 当前宿主通用写作要求与 Brief 展示存在冲突，未找到该宿主规则的本地可编辑源。后注入 developer 提示能否有效澄清，须在相同宿主下测量。
- 模型切换不触发本功能立即刷新，等待下次 SessionStart 才重新判断；关闭开关不会清理既有历史。对照实验必须固定 Astra 并隔离会话，宿主无法固定的模型内部修订需记录为限制。
- 六个场景的首轮重复试验只能支持有限样本结论，不能宣称长期稳定或彻底修复模型行为。
